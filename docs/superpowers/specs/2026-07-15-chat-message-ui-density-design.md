# Kith-space 聊天消息流密度与交互重构设计

- 日期：2026-07-15
- 状态：代码与自动化验证已完成，待用户手动视觉验收
- 范围：Chat 主消息流、话题消息流、Showcase 消息展示、消息工具与元信息、会话标题和消息区留白
- 当前实现基线：`de2a6db`
- 关联规格：`2026-07-10-kith-space-single-window-workspace-design.md`、`2026-07-14-chat-aggregate-panel-design.md`、`2026-07-14-agent-channel-response-mode-design.md`

> 本文把用户确认的消息 UI 密度方向固化为实现和验收规格。用户提供的第三方参考截图只用于提取布局关系、尺寸感和交互模式，不纳入仓库，也不复制其代码或品牌资产。当前生产事实仍以源码、`docs/kith-space/ui-direction.md` 与 `docs/progress.md` 为准；消息表现层和自动化回归现已落地，规定视口与真实交互的最终视觉验收依用户要求留待手动完成。

## 1. 决策摘要

当前聊天界面的“一个视图显示不了多少内容”不是页面缩放造成的。仓库没有额外设置 Electron `zoomFactor`、页面 `zoom` 或 `zoomLevel`；主要问题来自以下叠加：

- 每条消息使用整行、带描边的独立卡片，视觉块过重；
- 主消息列已被会话列表和 300px 聚合面板压缩，消息正文又在内容列内额外减去 64px；
- 正文虽然只有 14.5px，但行高为 1.68，长消息的累计高度偏大；
- 36px 头像、16px 昵称、重复 Agent 职责说明和正文前 8px 间距提高了每条短消息的固定高度；
- 会话标题下方 46px 渐变遮罩、消息区顶部 24px 留白和 Composer 112px 底部预留进一步压缩可见消息区。

本轮采用以下方案：

1. 把消息从“整行卡片”重构为“头像 + 元信息 + 内容气泡”的连续消息流。
2. Human 与 Agent 都保持左对齐；Human 使用浅蓝色气泡，Agent 使用中性浅灰气泡，系统消息继续居中。
3. 正文保持 14.5px，不采用全局缩放；行高收紧至 1.55，正文颜色提高到接近黑色。
4. 主消息行上限改为 900px，并让 Markdown 使用完整内容列，不再执行额外的 `calc(100% - 64px)`。
5. 头像统一为 32px，昵称收敛为 14.5px；Agent 职责描述不再在每条消息中重复，仍可从头像、昵称 hover 卡和 Agent 详情查看。
6. 保留现有响应模式徽标、收藏、复制、更多菜单、reaction、任务、话题、附件、消息深链和临时回复预览语义；Agent 在线状态只由头像右下角状态点表达，不在发送者行重复显示状态文字。
7. 话题入口改为气泡内的紧凑摘要：复用父消息批量元数据接口返回总数、未读、最后回复时间和最近三条轻量回复，不为每个话题单独发请求。
8. 会话标题改为 52px 紧凑标题栏，移除 46px 渐变遮罩；消息区上留白改为 14px，Composer 滚动预留目标改为 88px。

这不是对整个工作区的重新设计。顶部栏、Dock、会话列表、聚合面板、模块三态、话题正文位置和 Composer 交互继续遵守现有规格。

## 2. 目标与非目标

### 2.1 目标

- 在不牺牲正文可读性的前提下，提高同一视口内的消息密度。
- 让短消息轻、长消息稳，避免每条消息都形成同等重量的大卡片。
- 让 Human、Agent、系统消息和 action card 具有明确但克制的视觉差异。
- 扩大中文与中英混排消息的有效行宽，减少无意义换行。
- 让消息工具、响应模式和时间信息共存且不引起布局跳动。
- 让主消息流、话题消息流和 Showcase 共享同一消息表现层，消除三套相似 DOM。
- 保持 reaction、任务、话题、附件、归档只读、临时回复预览和消息深链行为不回退。
- 补齐悬停工具的键盘可达、辅助文字对比度和 reduced motion 行为。
- 把消息表现层从大型 `Chat.tsx` 和全局 `styles.css` 中拆出清晰边界。

### 2.2 非目标

- 不使用 Electron 缩放、CSS `zoom` 或把全局字号整体缩到 90% 一类捷径。
- 不改变 40px 顶部栏、常驻 Dock、ChatOnly / Split / ModuleOnly 三态和聚合面板的产品契约。
- 不重新设计 Composer 的 48px 紧凑态、附件、任务胶囊、`+` 菜单或 `@` 候选交互。
- 不修改消息、话题、reaction、任务、附件或响应模式的数据模型、API 和 Socket 协议。
- 不增加真实已读回执。当前没有面向消息 UI 的权威读者数据，不能从 Agent 在线状态、回复或轨迹推测“已读”。
- 不增加引用回复或 quote-reply 数据模型。参考界面的引用块只作为后续能力，不在首轮伪造。
- 不为每条父消息单独请求话题回复；最近三条预览必须随现有父消息批量元数据一次返回。
- 不跨发送者、日期分隔、系统消息或 action card 合并消息；仅隐藏同一天相邻 Human/Agent 普通消息的重复头像和发送者行。
- 不新增深色主题、气泡自定义颜色、密度偏好或用户可配置字号。
- 不顺手重做会话列表、聚合面板内容、Agent Profile、Tasks 或其他模块。

## 3. 当前问题与可验证事实

### 3.1 当前样式基线

| 项目 | 当前值 | 问题 |
|---|---:|---|
| 正文字号 | `14.5px` | 字号本身合理，不应继续明显缩小 |
| 正文行高 | `1.68`，约 `24.4px` | 长消息累计高度偏大 |
| 正文行宽 | `76ch` 上限，消息内再减 `64px` | 中文字符实际行宽偏窄，且重复扣减 |
| 消息头像 | `36px` | 元信息层级偏大 |
| 昵称 | `16px` | 与 14.5px 正文的差异过小但整体偏重 |
| 消息网格 | `44px + 12px` | 头像列和间隙合计 56px |
| 消息外观 | 整行描边、12px 圆角 | 每条消息都成为大卡片 |
| 消息间距 | 外边距 8px，内部另有多处 8px | 短消息的固定高度偏高 |
| 消息区留白 | 顶部 24px、底部 112px | 可见消息区被压缩 |
| 会话标题 | 24px 衬线字 + 46px 下方渐变 | 标题视觉过大，首条消息离标题过远 |
| ChatOnly 辅助面板 | 会话列表 210–260px、聚合面板 300px | 聚合面板打开时主列明显变窄 |

### 3.2 诊断优先级

影响从高到低为：

1. **有效宽度不足**：聚合面板打开时主列变窄，正文内部再减 64px，导致长内容过早换行。
2. **消息结构过重**：整行卡片、描边、阴影和统一宽度让短消息与长消息占据相似的视觉重量。
3. **固定壳层留白偏多**：标题渐变、顶部留白和过大的 Composer 预留减少可见消息区。
4. **行高和元信息偏松**：1.68 行高、36px 头像和 16px 昵称进一步增加高度。
5. **字色与字体气质**：正文偏灰、会话标题使用衬线字，让界面更像阅读面板而不是高频聊天工具。

因此，实现顺序必须先解决宽度、消息骨架和留白，再做字体微调。只把正文字号从 14.5px 改成 13px 不满足本规格。

## 4. 设计原则

### 4.1 气泡承载内容，消息行承载身份

头像、昵称、响应模式和时间属于发送者身份层，Agent 状态点附着头像；正文、附件、任务、reaction 和话题摘要属于消息内容层。外层消息行不再绘制卡片背景、边框或阴影。

### 4.2 两类发送者，保持同一阅读方向

Kith-space 是 Human 与一队 Agent 的协作工作面，不采用消费聊天应用常见的“Human 靠右、Agent 靠左”。Human 与 Agent 都左对齐，使用背景色区分：

- Human：暖色、轻量、短消息随内容收缩；
- Agent：中性浅灰、长内容自然扩展；
- System：无头像、无气泡、居中；
- Action card：复用发送者骨架，在气泡内部保留领域卡片层级。

### 4.3 保持可读字号，用结构换密度

正文目标仍为 14.5px。密度收益来自更宽的内容列、更紧的行高、更小的固定元信息和取消整行卡片，而不是让用户阅读更小的文字。

### 4.4 只展示真实状态

已读、交付、回复者、最近回复等状态只有在现有数据能权威支持时才显示。没有数据时不留空白占位，不根据 Agent 在线、轨迹或回复行为猜测。

### 4.5 视觉重构不得改变领域行为

消息 UI 可以移动控件、调整层级和样式，但不能改变：

- 消息发送者、时间、正文和附件事实；
- response mode 的显示适用范围和编辑规则；
- reaction、收藏、复制、任务、话题和归档只读规则；
- deep link、消息高亮、分页、滚动锚定和实时预览收敛；
- Showcase 和 action card 的只读或执行边界。

## 5. 目标消息结构

### 5.1 通用结构

```text
消息行（无卡片背景）
├─ 32px 头像 / 在线点
└─ 内容列
   ├─ 发送者行
   │  ├─ 昵称
   │  ├─ 响应模式徽标（适用时）
   │  ├─ 时间
   │  └─ 时间
   └─ 内容气泡
      ├─ 正文 / 临时回复预览 / action card
      ├─ 附件
      ├─ 任务与 reaction
      └─ 话题摘要（存在回复时）
```

建议语义结构：

```tsx
<article className="chat-message chat-message--agent" aria-labelledby={headerId}>
  <MessageAvatar />
  <div className="chat-message__content">
    <MessageHeader />
    <MessageBubble>
      {body}
      {attachments}
      {meta}
      {topicSummary}
    </MessageBubble>
    {authoritativeReceipt}
  </div>
    <MessageToolbar />
</article>
```

首轮 `authoritativeReceipt` 始终为空；该槽位只定义未来位置，不生成 DOM 占位。

### 5.2 Human 消息

- 保持左对齐并显示 Human 头像、昵称和时间。
- 气泡使用暖色背景，`width: fit-content`、`max-width: 100%`。
- 一行短消息只包住正文，不扩展成整行色块。
- 长 Markdown、附件、任务或话题摘要自然扩展到内容列上限。
- Human 设置入口继续由头像和昵称打开，不改变为右键或菜单动作。

### 5.3 Agent 消息

- 使用中性浅灰气泡，短消息同样允许随内容收缩，长消息接近内容列宽度。
- 在线点继续附着头像。
- 频道与话题中的响应模式徽标继续位于昵称后；DM、Human、系统消息和已移除 Agent 不显示。
- Agent 在线/工作/休眠状态只由头像右下角状态点表达，发送者行不再重复显示文字状态。
- Agent 职责描述不再在每条消息下重复；头像/昵称 hover 卡和 Agent 详情仍提供完整信息。

### 5.4 系统消息

- 继续居中，无头像、无气泡。
- 字号 12px、行高 1.4，颜色必须达到普通小字号文字的可读对比度。
- 可附带既有话题入口，但不伪装为 Human 或 Agent 消息。

### 5.5 Action card 与 Agent 临时回复预览

- `ActionCardMessage` 复用同一头像、发送者行和气泡外壳；领域内容保留自己的按钮、完成态和错误态。
- Agent 临时回复预览使用 Agent 气泡，不再使用整行卡片。
- 预览进入、收敛为正式消息和被话题正式回复移除的行为保持不变。
- Shimmer 只作用于预览文字，不让整个气泡闪烁。

## 6. 尺寸与视觉 Token

### 6.1 新增消息专用 Token

Token 放在消息样式模块或根主题中，避免继续散落魔法值：

```css
--chat-stream-max: 900px;
--chat-message-avatar: 32px;
--chat-message-gap: 10px;
--chat-message-font-size: 14.5px;
--chat-message-line-height: 1.55;
--chat-message-radius: 10px;
--chat-message-agent-bg: #f6f6f4;
--chat-message-agent-bg-hover: #f2f2ef;
--chat-message-human-bg: #eff4fb;
--chat-message-human-bg-hover: #e6eef8;
--chat-message-text: #292524;
--chat-message-meta: #777169;
--chat-composer-reserve: 88px;
```

这些颜色属于消息语义，不复用 `--mention`、`--g-peach` 或状态色，以免 Human 气泡与 mention、告警或响应模式混淆。

### 6.2 布局基线

| 元素 | 目标值 |
|---|---:|
| 消息流最大宽度 | `900px` |
| 消息区左右内距 | 桌面 `20px`，紧凑 `16px` |
| 消息区顶部内距 | `14px` |
| 消息行网格 | `32px minmax(0, 1fr)` |
| 头像与内容间距 | `10px` |
| 消息行底部间距 | `20px` |
| 气泡内距 | `8px 14px` |
| 气泡圆角 | `10px` |
| 发送者行与气泡间距 | `4px` |
| 气泡内部元信息上间距 | `6px` |
| 日期分隔上下间距 | `10px` |
| 消息工具按钮 | `30px × 30px` |
| 会话标题栏 | `52px` |
| Composer 滚动预留 | `88px` |

外层消息行必须满足：

- 无背景；
- 无边框；
- 无阴影；
- 无左右内边距；
- 宽度上限与 Composer、日期分隔线使用同一 `--chat-stream-max`；
- 主消息流和话题消息流不再使用两套头像尺寸。

### 6.3 字体基线

| 文本 | 字号 | 行高 | 字重 / 颜色 |
|---|---:|---:|---|
| 会话标题 | `20px` | `1.2` | `600`，`--ink`，仅 Chat 标题使用 sans |
| 昵称 | `14.5px` | `20px` | `700`，`--ink` |
| 正文 | `14.5px` | `1.55` | `400`，`--chat-message-text` |
| 时间 | `11px` | `16px` | `400`，`--chat-message-meta` |
| 任务 / reaction / 话题摘要 | `11.5–12px` | `1.4` | 依现有状态，普通文字不低于 4.5:1 |

消息正文不继承全局 `letter-spacing: .15px`，使用 `letter-spacing: 0`，避免中文正文额外变宽。

### 6.4 Markdown 密度

- `.msg .md` 等旧选择器改为消息模块内的局部选择器。
- Markdown `max-width: 100%`，不再执行 `calc(100% - 64px)`。
- 段落间距从 `.75em` 收敛到 `.6em`。
- 列表上下间距从 `.65em` 收敛到 `.5em`，列表项间距从 `.18em` 收敛到 `.12em`。
- 标题、代码块、表格和 GitHub alert 保持现有语义与渲染安全，不为了密度删除必要内距。
- 代码块和表格可以占满气泡内容宽度；纯正文不再额外套一层较窄阅读列。

## 7. 会话标题、消息区与 Composer 边界

### 7.1 会话标题

- 只调整 `.chat-head`，不改变 Agents、Settings 等共用 `.head`。
- 高度固定为 52px，左右内距 20px，标题使用 20px sans、600 字重。
- 现有左侧会话列表开关和右侧任务、成员、聚合面板、设置动作保持顺序和 30px 点击区。
- 删除向下覆盖消息区的 46px 渐变伪元素。
- 使用 1px 内部分隔线建立标题与消息区边界，不新增主面板阴影。

### 7.2 消息滚动区

- 顶部内距从 24px 改为 14px。
- 左右内距从 28px 改为 20px；Chat 紧凑宽度下使用 16px。
- 底部内距从固定 112px 改为 `var(--chat-composer-reserve)`，初始目标 88px。
- 首条消息不得被标题层或渐变遮挡。
- 旧消息分页、prepend 高度恢复、底部锚定和“回到底部”按钮行为不变。
- “回到底部”按钮的位置由 Composer 预留 Token 计算，不再保留 154px 的独立魔法值。

### 7.3 Composer

- 继续保持 48px 紧凑态、32px `+` / 发送按钮和现有展开规则。
- Composer 外框最大宽度改用同一 `--chat-stream-max`，与消息行和日期分隔对齐。
- 不改变菜单、附件、任务胶囊、候选列表、快捷键或发送逻辑。
- Composer 自身高度变化时，现有滚动锚定必须继续把当前 live tail 保持在可见区域。

## 8. 消息交互细节

### 8.1 发送者行

顺序固定为：

```text
昵称 → 响应模式徽标 → 时间
```

- 昵称过长时省略；响应模式徽标和时间不能被昵称挤出。
- 时间默认透明但保留布局占位，hover 整条消息或消息内控件获得焦点时显示；当天只显示 `HH:mm`，历史消息显示完整日期与时分，无 hover 设备常驻显示。
- 响应模式徽标的 hover、点击、键盘聚焦和只读规则完全复用现有 feature。
- Agent 与 Human 昵称均使用粗体；Agent 状态文字不进入发送者行。

### 8.2 消息工具栏

外显动作固定为：加表情、发起/打开话题、复制 Markdown、更多菜单；收藏/取消收藏继续位于“更多”菜单。

- 默认隐藏，不占据额外高度。
- 只有 `.chat-message__bubble-wrap:hover` 或气泡/工具自身 `:focus-within` 时显示；hover 头像、昵称或消息行空白区不能触发工具栏。
- 工具栏默认锚定在气泡右侧；气泡右侧到当前可视消息边界不足以容纳工具栏时，切换到气泡上方右对齐。位置计算只在进入气泡或键盘聚焦时执行，不为每条消息建立常驻窗口监听。
- 键盘 Tab 到任一工具按钮时，该按钮和整个工具栏可见。
- 每个按钮为 `30px × 30px`，保留 Tooltip、`aria-label` 和清晰焦点反馈。
- 右键菜单仍可从整个消息行打开；“更多”按钮继续打开同一菜单。
- 触控或无 hover 环境至少保留可见“更多”入口，不能让收藏、复制、reaction、话题或转任务完全不可达。
- 工具出现和消失只改变 opacity/visibility，不触发消息内容重排。

### 8.3 气泡 hover 与焦点

- Hover 只把气泡背景轻微加深，不绘制整行底色或大阴影。
- `:focus-within` 使用 1px–2px 内描边，不能依赖浏览器默认黑框。
- 深链高亮作用于气泡和必要的头像边缘，不恢复整行大色块。
- 归档只读消息仍允许复制、收藏和打开既有话题；被关闭的写动作不因样式重构重新出现。

### 8.4 任务、reaction 与话题摘要

气泡内容顺序固定为：

```text
正文 / action card
附件
任务与 reaction 元信息
话题摘要
```

- 任务 pill 和 reaction chip 继续位于同一元信息区，自动换行但不产生空行。
- 没有任务、reaction 或话题时不渲染空容器。
- 有话题回复时，在气泡底部展示整行可点击摘要，正文与摘要之间不绘制分隔线；摘要包含参与者头像、回复数、最近三条 Human/Agent 回复和最新时间，点击继续打开现有 `ThreadPanel`。
- 最近回复由父消息批量 thread metadata 的权威 `previews` 字段提供；system 任务事件保留在话题记录和总回复数中，但不占用预览名额。
- 聚合面板“话题”Tab 继续提供完整话题索引；气泡摘要只是当前父消息的快捷入口。

### 8.5 已读状态预留

参考界面的“某 Agent 看过了”属于真实读回执，不是纯视觉装饰。本轮规则为：

- 不新增 API，不从 `online`、`sleeping`、轨迹或是否回复推断已读；
- 没有权威读者数据时不渲染任何占位；
- 后续若增加消息级权威读者 DTO，回执位于 Human 气泡下方、与气泡左边界对齐，字号不超过 11.5px；
- 该后续能力必须另有领域与隐私规格，不在本视觉重构中顺带实现。

## 9. 附件、复杂内容与状态变体

### 9.1 图片、视频和文件

- 附件位于气泡内部，继续使用现有预览、Lightbox、下载、错误降级和 MIME 判断。
- 图片和视频不超过气泡内容宽度；窄视口不产生横向滚动。
- 文件卡片可以保留自身边框，但避免与外层气泡形成两层同等强度的描边。
- 只有附件、没有正文的消息仍显示气泡。

### 9.2 代码、表格与长链接

- 代码块、表格和长链接继续 `overflow-wrap` / 内部滚动，不撑破 Chat Pane。
- 表格优先在气泡内部横向滚动，不让整个页面产生横向滚动。
- 复制代码、复制 Markdown 和链接安全策略保持不变。

### 9.3 日期、系统消息和加载骨架

- 日期分隔最大宽度与消息流一致，上下间距改为 10px。
- 系统消息保持无头像的居中轻量行。
- `ChatSkeleton` 的头像改为 32px，骨架正文改成气泡形态，不继续预示旧的大卡片结构。
- 加载失败、空频道和归档提示仍由各自现有组件负责，不套消息气泡。

### 9.4 Showcase

- Showcase 消息使用同一 `ChatMessageItem` 表现层和 `surface="showcase"` 变体。
- Showcase 保持只读；不显示消息工具中会写入数据的动作。
- 角色标签可以保留在发送者行，但不恢复每条消息下方的职责描述行。
- Showcase case 自身的外层卡片层级不与消息气泡重复绘制边框。

## 10. 话题消息流与紧凑 Chat

### 10.1 话题消息

当前 `ThreadMsg` 使用另一套 32px 头像和近似消息 DOM。本轮将它收敛为同一 `ChatMessageItem`：

- `surface="thread"` 使用相同头像、字体、气泡、工具和元信息；
- 话题父消息区域继续保留现有浅色父消息容器，但父消息内部使用新消息骨架；
- 话题回复 Composer、关注、完成、跳回原消息和拖拽宽度不变；
- 话题内部不再显示指向自身的重复话题摘要。

### 10.2 Chat 紧凑宽度

- Chat Pane 处于既有最小宽度时，消息区左右内距 16px、头像仍为 32px、间距可降为 8px。
- 正文字号不随 Chat Pane 变窄而减小。
- 昵称优先省略，响应模式徽标、时间和更多入口保持可达。
- 复杂 Markdown、附件和 meta 区允许内部换行，不产生页面级横向滚动。
- 聚合面板或 Module 的显隐规则继续由 `WorkspaceFrame` / `paneConstraints` 控制，消息组件不读取模块状态。

## 11. 响应式与缩放

必须覆盖以下状态：

| 视口 / 面板 | 验收重点 |
|---|---|
| `1423×912` ChatOnly + 聚合面板 | 与当前用户截图同类状态，验证密度与主列宽度 |
| `1280×800` ChatOnly | 常见桌面窗口，消息、Composer、Dock 不重叠 |
| `1024×768` 响应式边界 | 聚合面板按现有规则隐藏，消息流自然扩展 |
| `360px` Chat Pane | Split 最小 Chat，正文、工具、附件不溢出 |
| 话题五五开 | 主消息与话题消息使用同一视觉语言 |
| 浏览器 200% 缩放 | 允许纵向增长，不出现不可达按钮或横向页面滚动 |

本规格不改变全局断点。能由 CSS Grid、`max-width: 100%` 和现有 Chat Pane 宽度解决的问题，不增加新的 JavaScript 窗口监听。

## 12. 无障碍要求

- 消息正文使用 `#292524` 或等效高对比颜色。
- 12px 以下的辅助文字不得继续使用白底约 2.5:1 的 `#a8a29e`；普通小字号目标至少 4.5:1。
- 消息工具、话题摘要、reaction、任务和头像入口必须有可见键盘焦点。
- Hover 才出现的控件必须同时支持 `:focus-within`；无 hover 环境保留可达入口。
- 工具按钮最小 30px，不能照搬参考界面更小的触控目标。
- 消息行使用 `article` 或等效语义，发送者与时间形成可读标签；不要给每个装饰图标增加重复读屏文本。
- 状态变化不能只靠颜色；响应模式、任务、未读话题和收藏继续有文案或可访问名称。
- `prefers-reduced-motion: reduce` 下关闭消息进入位移和工具栏过渡，但保留最终状态。
- 200% 缩放和窄 Pane 下 DOM 阅读顺序仍为头像/发送者、正文、附件、元信息、话题摘要、工具动作。

## 13. 前端模块边界

### 13.1 新目录

建议新增：

```text
web/src/views/chat-message/
├─ ChatMessageItem.tsx
├─ MessageHeader.tsx
├─ MessageBubble.tsx
├─ MessageMeta.tsx
├─ MessageToolbar.tsx
├─ messagePresentation.ts
└─ chatMessage.css
```

文件可以在实现时按仓库风格合并较小组件，但必须保持以下职责：

- `ChatMessageItem`：纯表现骨架和 sender/surface 变体，不请求数据、不操作路由；
- `MessageHeader`：发送者、响应模式 slot 与时间；Agent 状态只由头像状态点表达；
- `MessageBubble`：正文、附件、meta、话题摘要的背景和内距；
- `MessageMeta`：任务、reaction、话题摘要的布局，不拥有任务或 reaction 请求；
- `MessageToolbar`：加表情、话题、复制、更多入口、气泡锚定位置及键盘可见性；收藏保留在更多菜单；
- `messagePresentation`：仅在确有必要时保存纯 class/variant 推导，不创建通用规则引擎；
- `chatMessage.css`：消息专用 Token、变体和响应式，不继续把规则堆入全局 `styles.css`。

### 13.2 `Chat.tsx` 保留的职责

`Chat.tsx` 继续负责：

- 当前会话消息加载、分页、实时事件与滚动锚定；
- Agent / Human 数据解析；
- response mode feature 的数据与 slot；
- 收藏、复制、reaction、任务、话题和上下文菜单回调；
- 归档、Showcase、消息高亮和临时回复预览状态。

它把已解析的 ReactNode 和事件回调传给表现组件，不把 API、Store 或 Router 注入每个小组件。避免为一次使用建立庞大 Message UI Context。

### 13.3 复用范围

以下入口必须复用同一骨架：

- Chat 主消息列表；
- `ThreadMsg` 话题回复；
- `ActionCardMessage` 外层；
- Showcase 消息；
- Agent 临时回复预览；
- 对应 Skeleton。

附件卡片、Markdown renderer、response mode feature、reaction、任务菜单和上下文菜单继续作为现有独立能力被组合，不在消息目录复制实现。

## 14. 数据、API 与安全边界

- workspace.db schema 保持 v5 和现有 19 张产品表。
- 不新增消息读者表、reply-to 字段、话题预览字段或气泡偏好。
- 不修改 `/api/messages`、`/threads`、`/files`、reaction、任务或 Agent 设置 API。
- 不新增每消息、每话题或每 Agent 的额外请求。
- 话题摘要消费 `threadMeta` 的 `replyCount`、`unreadCount`、`followed`、`lastReplyAt` 与最多三条 `previews`；初始页面和历史分页按父消息 ID 批量加载，实时 `thread:updated` 只针对变更父消息刷新同一接口。
- response mode badge 继续通过现有每频道一次装载和窄实时失效，不退回每条消息请求。
- 消息正文继续使用现有 Markdown schema、URL transform、HTML-as-text 和附件安全边界。
- 归档频道的写入 guard、Showcase 只读、Space 隔离和 Human authority 不因 UI 重构改变。

若实现过程中发现视觉目标必须依赖新数据，停止该子项并另写增量规格；不得在前端猜测或从无关事件拼装。
