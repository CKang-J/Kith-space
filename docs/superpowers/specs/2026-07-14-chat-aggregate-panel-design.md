# Kith-space 会话聚合面板与会话级轨迹设计

- 日期：2026-07-14
- 状态：用户已确认，待实现
- 范围：Chat 工作面、聚合面板、话题入口、会话任务入口、会话附件筛选、实时轨迹作用域
- 当前实现基线：`f1314a8`

> 本文描述下一轮 UI 与事件作用域改造的目标状态。实现完成前，当前生产事实仍以
> `docs/kith-space/ui-direction.md` 和 `docs/kith-space/architecture-proposal.md` 为准；实现 PR 必须同步更新这两份权威文档。

## 1. 决策摘要

当前 Chat 顶部存在一条独立的“会话 / Chat / 轨迹”工具栏，频道标题区又包含“对话 / 任务 / 文件 / Agents”等入口，右侧固定栏只承载全 Space 的实时轨迹。入口重复、右侧空间职责过窄，而且实时轨迹会混入其他会话的活动。

本轮把右侧栏改造成**当前会话的聚合面板**：

- 删除“会话 / Chat / 轨迹”独立顶栏。
- 会话列表开关迁入当前会话标题栏最左侧，位于频道或私信标题之前。
- 标题栏移除“对话”Tab；“任务”改为纯图标快捷入口，直接打开当前会话作用域的 Tasks 模块。
- 原“Agents”入口改为纯图标“成员”入口，继续承载当前会话的成员行为。
- “成员”右侧增加纯图标聚合面板开关。
- “轨迹 / 话题 / 文件”进入聚合面板，通过带滑动底板动画的 Tab 切换。
- 聚合面板在没有模块时位于 Chat 右侧；模块打开时位于 Chat 与 Module 之间，不再退化为覆盖 Chat 的轨迹抽屉。
- 实时轨迹按当前会话隔离。没有明确会话归属或跨多个会话的轨迹不得猜测归属，也不得出现在会话聚合面板中。
- 用户可见的中文“线程”统一改为“话题”；代码、路由、API、数据库与事件中的内部标识继续使用 `thread`。

这不是任意停靠的通用面板系统。聚合面板是 Chat 的会话级辅助工作面，Module Pane 仍保持一次只打开一个模块的既有规则。

## 2. 目标与非目标

### 2.1 目标

- 合并 Chat 内重复入口，让标题区成为当前会话操作的唯一入口。
- 用一个稳定聚合面板承载当前会话的轨迹、话题列表和文件列表。
- 在 ChatOnly 与 Split 中保持相同的聚合面板语义和位置。
- 让 Tasks 快捷入口始终打开当前频道或私信的任务，而不是 Chat 内嵌任务页。
- 为文件提供“全部 / 图片 / 视频 / 文件”分类和文件名、来源消息搜索。
- 让话题列表覆盖当前会话的全部话题，而不是只依赖当前已加载的消息页。
- 从事件产生端补齐轨迹会话作用域，禁止前端按当前页面或 agent 身份猜测归属。
- 保持既有话题正文面板的位置、宽度、关注行为和模块联动策略。
- 复用同一滑动 Tab 组件，统一聚合面板等分 Tab 的动画和无障碍行为。

### 2.2 非目标

- 不把文件或话题提升为新的 Dock 模块。
- 不在聚合面板内部渲染话题正文。
- 不修改 thread 的内部英文代号，不迁移 `thread` 路由参数、数据库类型或 API 命名。
- 不增加跨 Space 文件、话题或轨迹聚合。
- 不把无法确定会话归属的后台活动强行分配给当前会话。
- 不在本轮增加轨迹数据库迁移或长期会话轨迹归档；聚合面板保持现有“本次前端会话内的有界实时缓冲”语义。
- 不在本轮增加聚合面板拖拽改宽；先保持稳定默认宽度和响应式约束。
- 不改变现有话题面板的拖拽改宽、关注/取消关注、关闭和跳回原消息行为。

## 3. 术语

| 层级 | 规范用词 | 说明 |
|---|---|---|
| 中文产品界面 | 话题 | 替换所有用户可见的“线程”文案、标题、提示、空状态和无障碍标签 |
| 内部代码与协议 | `thread` | 继续使用 `threadChannelId`、`threadParam`、`thread:updated`、`type="thread"` 等既有名称 |
| 聚合面板 | Conversation Aggregate Panel | 当前会话的辅助工作面，包含轨迹、话题、文件三个 Tab |
| 当前会话 | base conversation | 当前频道或 Human-Agent DM；话题属于其父会话，不成为新的聚合面板作用域 |
| 轨迹作用域 | trajectory scope | 一段轨迹可以可靠归属的目标 channel/thread 及其父会话 |

国际化 key 可以继续使用既有 `thread` 命名，避免为了文案变化重命名内部键；中文展示值必须统一为“话题”。

## 4. 目标信息架构

### 4.1 ChatOnly

聚合面板关闭：

```text
会话列表 | 当前会话 / 话题与 Composer
```

聚合面板打开：

```text
会话列表 | 当前会话 / 话题与 Composer | 聚合面板
```

会话列表仍可独立收起到宽度 `0`，不保留贯穿全高的收起长条。聚合面板也以宽度 `0` 收起，不保留占位栏。

### 4.2 Split（Chat + Module）

聚合面板关闭：

```text
Chat | Module
```

聚合面板打开：

```text
Chat | 聚合面板 | Module
```

聚合面板是 Chat 和 Module 的同级视觉面板，物理位置固定在两者之间。它不覆盖、不遮挡 Module，也不再作为 Chat 内部轨迹抽屉打开。

### 4.3 ModuleOnly

```text
Module
```

聚合面板依赖当前可见 Chat 的会话上下文。进入 `chat=0` 时暂时隐藏，但保留用户的打开意图；恢复 Chat 后，宽度允许时恢复此前的聚合面板状态。系统不允许在 Chat 不可见时单独显示聚合面板。

### 4.4 话题与 Module 并存

- 没有 Module 时，打开话题继续让当前会话与话题正文默认五五开，并保留中间拖拽分割线。
- Module 已打开时，紧凑 Chat 继续只显示话题正文，不再同时并排显示父会话消息流。
- 聚合面板打开时仍位于 Chat/话题工作面与 Module 之间。
- 从聚合面板点击话题不会把正文渲染在聚合面板中，也不会自动关闭聚合面板；聚合面板显隐继续由用户自己的开关控制。

## 5. 当前会话标题栏

删除 `shell-chat-compact-tools` 整条顶栏。频道或私信标题栏成为当前会话操作的唯一入口：

```text
[会话列表开关]  #频道 / @私信标题  ……  [任务] [成员] [聚合面板] [更多]
```

### 5.1 会话列表开关

- 位于标题最左侧、会话名称之前，使用纯图标。
- ChatOnly 中控制固定会话列表收起/展开。
- Split 中继续控制会话抽屉，保持当前紧凑 Chat 行为。
- 展开和收起使用 Chat 侧栏自己的边界运动曲线，不复用 Module Pane 的切换曲线。
- 图标和 `aria-label` 必须随状态表达“收起对话列表”或“展开对话列表”。

### 5.2 任务快捷入口

- 移除 Chat 内的“任务”文字 Tab，改为纯图标按钮。
- 点击始终导航到 `module=tasks&taskScope=<当前会话ID>`。
- 从 ChatOnly 点击时进入 Split；Module 已打开时直接把当前 Module 替换为 Tasks。
- 如果已经打开当前会话的 Tasks，点击保持当前页面，不把它解释为关闭模块。
- 频道和 Human-Agent DM 都使用自己的 channel ID 作为 `taskScope`。

### 5.3 成员入口

- 原“Agents”文字按钮改为纯图标“成员”按钮。
- 频道中继续打开当前频道的成员管理能力，不改成 Agents 模块导航。
- Human-Agent DM 已有的 agent 详情快捷入口继续保留，不用“成员”按钮伪造多人语义。
- 纯图标必须有“成员”Tooltip、`aria-label` 和清晰的键盘焦点样式。

### 5.4 聚合面板开关

- 位于成员图标右侧，使用纯图标。
- 控制聚合面板宽度在 `0` 与目标宽度之间变化。
- 使用 `aria-pressed` 表达打开状态；宽度不足导致临时隐藏时应说明当前不可展开，而不是响应点击后无反馈。
- Saved、Showcase 等没有单一当前会话作用域的页面不显示该入口。

## 6. 聚合面板

### 6.1 面板结构

```text
┌──────────────────────────────┐
│ [轨迹] [话题] [文件]          │  ← 滑动 Tab
├──────────────────────────────┤
│ 当前 Tab 的工具区             │
├──────────────────────────────┤
│ 当前会话内容                  │
└──────────────────────────────┘
```

- 三个 Tab 顺序固定为“轨迹 / 话题 / 文件”。
- 第一次打开默认显示“轨迹”，保持原右侧实时轨迹栏的主要用途。
- 本次应用会话中记住最后选中的 Tab；切换频道或 DM 时面板保持打开和当前 Tab，但内容立即切换到新会话。
- 切换 Space 时清空聚合数据和临时状态，不能带入前一个 Space 的内容。
- 面板开关和当前 Tab 属于短暂 UI 状态，不写入 URL。

### 6.2 通用滑动 Tab 组件

新增通用 `SlidingTabs` 组件，聚合面板只负责传入选项和当前值，不自行复制滑块 DOM 与动画。

组件契约建议保持最小：

```ts
interface SlidingTabOption<T extends string> {
  value: T;
  label: ReactNode;
  disabled?: boolean;
}

interface SlidingTabsProps<T extends string> {
  value: T;
  options: readonly SlidingTabOption<T>[];
  onChange(value: T): void;
  ariaLabel: string;
}
```

行为要求：

- 外壳是浅灰圆角槽，选中项由一块独立白色圆角底板表达。
- 底板通过 `transform` 和必要的宽度变化在选项之间横向滑动；内容不做淡入淡出。
- 选项等宽时只移动 `translateX`，避免每次点击测量布局。
- 使用 `role="tablist"`、`role="tab"`、`aria-selected` 和关联 `tabpanel`。
- 支持左/右方向键、Home/End 和 Enter/Space。
- `prefers-reduced-motion: reduce` 下取消滑动时长，但保持状态变化可见。
- 组件不包含聚合面板、文件筛选或路由业务，避免把单一场景写进通用层。

文件页的“全部 / 图片 / 视频 / 文件”是筛选胶囊，不使用 `SlidingTabs`，因为它们是数据过滤器，不是同级页面导航。

## 7. 话题 Tab

### 7.1 数据范围

- 展示当前频道或 Human-Agent DM 中已经创建的全部话题。
- 不能只从当前已加载的消息窗口推导，否则较早消息下的话题会消失。
- 默认按最后回复时间倒序；没有回复时按话题创建时间倒序。
- 每项至少展示父消息摘要、发起者、回复数、未读数和最后活动时间；关注状态可作为次要状态展示。

现有 `GET /api/channels/:channelId/threads?parentMessageIds=...` 只服务当前消息页的批量元数据。实现时新增明确的内部 thread summary 查询能力，继续使用 `thread` 英文命名，并复用既有频道可读权限检查；不引入 `topic` 数据模型，也不需要数据库迁移。

### 7.2 点击行为

- 点击列表项设置既有 `thread` 聚焦参数，调用现有话题打开链路。
- ChatOnly 中在原位置打开父会话 + 话题正文的五五开布局。
- Split 中按现有策略让紧凑 Chat 只显示话题正文。
- 聚合面板只提供索引和入口，不复制 `ThreadPanel`、回复 Composer、关注按钮或关闭按钮。
- 浏览器前进/后退继续恢复既有 thread 聚焦；内部路由参数保持 `thread`，不增加 `topic` 别名。

### 7.3 实时更新

- 当前会话的 `thread:updated` 事件更新回复数、未读和排序。
- 新创建的话题应进入列表；删除、归档或完成后的可见性遵循现有 thread 领域规则。
- 切换会话时取消旧请求结果落地，禁止旧会话列表闪现在新会话中。

## 8. 文件 Tab

### 8.1 数据范围与列表

- 复用当前 `/api/channels/:channelId/files` 的当前 Space、当前会话和成员权限边界。
- 频道和 Human-Agent DM 都可展示自己的附件。
- 保持当前按上传时间倒序、点击预览/下载、跳到来源消息的行为。
- 首轮继续沿用当前最多 100 条的有界列表，不在本轮顺带增加分页。

### 8.2 分类筛选

筛选项固定为：

| 筛选项 | 判断规则 |
|---|---|
| 全部 | 不限制 MIME 类型 |
| 图片 | `mimeType` 以 `image/` 开头 |
| 视频 | `mimeType` 以 `video/` 开头 |
| 文件 | 除图片和视频外的所有附件，包括 MIME 缺失项 |

- 分类使用胶囊按钮，当前项采用高对比选中态。
- 分类与搜索条件取交集，不互相清空。
- 分类只是客户端对已加载会话附件的筛选，不新增四套 API。

### 8.3 搜索

- 工具区默认显示圆形搜索图标。
- 点击后在分类行下方展开搜索框并自动聚焦，使用横向尺寸动画，不做透明度渐变。
- 占位文案为“搜索文件或消息…”。
- 搜索按去除首尾空格后的不区分大小写文本，同时匹配附件文件名和来源消息正文。
- `/api/channels/:channelId/files` 需要在同一权限查询中返回必要的来源消息摘要；前端不为每个附件再发一次消息请求。
- 清空查询后可以收回搜索框；存在查询时切换分类应保留搜索词。

### 8.4 空状态

- 当前会话没有任何附件：显示“暂无文件”。
- 有附件但分类或搜索无结果：显示“没有匹配的文件”，并提供清除筛选入口。
- 请求失败：在文件 Tab 内显示重试，不影响 Chat、话题或轨迹 Tab。

## 9. 轨迹 Tab 与会话隔离

### 9.1 当前问题

当前前端 `traj` 是 Store 中的全 Space 有界缓冲；`TrajItem` 只有 agent 名称、文本、工具和边界标记。Worker 产生的 `agent:trajectory`、Core 发布的 `trajectory` 以及 Socket.IO 合并后的 `agent:activity` 都没有会话 ID，因此前端无法正确按会话过滤。

本轮不能用“当前页面打开哪个频道就把新事件算给哪个频道”的补丁式方案。页面切换、后台 agent、跨会话批量唤醒都会造成错误归属。

### 9.2 规范作用域

轨迹作用域使用内部 thread/channel 事实，最终归一到父会话：

```ts
interface TrajectoryScope {
  channelId: string;       // 实际唤醒目标，可能是频道、DM 或 thread channel
  conversationId: string;  // 频道/DM 根会话；thread 归一到其父消息所在会话
  streamId?: string;
}
```

- 单一明确目标：携带完整 scope，进入该 `conversationId` 的缓冲。
- 目标是 thread：`channelId` 保留 thread channel，`conversationId` 使用父频道或父 DM。
- 手动启动、定时后台工作等没有目标会话：scope 为空，不进入任何会话聚合面板。
- 一次 runtime turn 同时合并多个不同父会话：标记为 ambiguous，不猜测、不复制到多个会话；仍保留在 Agent 自身活动记录中。
- 多个目标若不能在产生端可靠证明属于同一父会话，也按 ambiguous 处理。

### 9.3 事件链路

作用域必须沿完整链路传递：

```text
AgentManager delivery context
  → agent:trajectory（Worker）
  → trajectory publish（Core）
  → agent:activity entries（Socket.IO）
  → Store conversation trajectory buffer
  → 聚合面板当前 conversationId
```

实现要求：

- Worker 在唤醒/投递时维护独立、可测试的 trajectory scope，不直接把 `activeReplyPreview` 的最后一个目标当成永远正确的会话归属。
- Core 根据实际 target channel 解析 thread 的父会话，并附加 `conversationId`。
- Socket payload 保留 `channelId`、`conversationId` 和可用的 `streamId`。
- 前端把单一全局 `traj` 改为按 `conversationId` 分桶的有界缓冲；每个会话独立执行容量裁剪。
- turn 结束边界必须写入同一 `conversationId + agentId + streamId`，不能再由无作用域的 agent 状态给全局缓冲追加边界。
- 切换会话只切换当前分桶，不清空其他会话本次应用会话内的缓冲；切回后可以继续看到该会话最近轨迹。
- 切换 Space 时清空全部会话轨迹分桶。

### 9.4 展示规则

- 轨迹 Tab 只读取当前 base conversation 的缓冲。
- 父频道中的话题轨迹属于同一父会话，可在该频道的轨迹 Tab 中显示。
- 其他频道、其他 DM、无作用域和 ambiguous 轨迹绝不出现。
- Agent 详情“活动”页继续承担 agent 维度的全局活动查看，不受会话面板筛选限制。
- 无轨迹时显示当前会话级空状态，不再使用暗示全 Space 的说明文案。

## 10. 路由与状态边界

### 10.1 进入 Tasks

标题栏任务图标使用既有 `workspaceLocationForModule`，目标为：

```ts
{ moduleId: "tasks", taskScope: currentConversationId }
```

它是明确导航，不复用 Dock 的“点击当前模块即关闭”语义。

### 10.2 打开话题

- 继续使用既有 `thread` query 聚焦。
- 切换频道或 DM 时继续移除旧 `thread` 和 `msg` 临时焦点。
- 聚合面板自身的打开状态、当前 Tab、文件分类和搜索展开状态不进入 URL。

### 10.3 本地 UI 状态

- 聚合面板打开意图和当前 Tab 在当前前端会话中保留。
- 文件筛选和搜索词按当前会话保存于组件状态；切换会话时重置为“全部 + 空搜索”，避免把一个频道的查询误认为另一个频道的状态。
- 响应式临时隐藏不覆盖用户的打开意图，窗口恢复后可自动恢复。

## 11. 模块边界与代码拆分

### 11.1 顶层职责

- `WorkspaceFrame`：继续负责 Chat、聚合面板、Module 的编排和响应式约束；不读取文件、话题或轨迹业务数据。
- `ChatWorkspace`：负责会话列表和 Chat 主工作面；移除固定实时轨迹栏和轨迹抽屉职责。
- `ConversationAggregatePanel`：只负责三个 Tab、面板工具区和当前会话 ID 分发。
- `Chat`：继续负责消息、话题正文和 Composer；通过窄 props/slot 接收标题栏外壳操作，不直接拥有聚合面板状态。

### 11.2 子视图

聚合面板的三个子视图独立拆分：

- `ConversationTrace`：按 `conversationId` 读取轨迹缓冲并复用 `LiveTrace` 的渲染能力。
- `ConversationTopics`：加载 thread summaries，并通过既有路由打开话题。
- `ConversationFiles`：从当前 `ChannelFiles` 抽出，增加分类和搜索。
- `SlidingTabs`：通用纯 UI 组件，不导入 Store、路由或聚合面板类型。

不要继续把文件筛选、话题列表和聚合面板状态堆入已经较大的 `Chat.tsx`。

### 11.3 服务端与 Worker

- thread summary 查询从路由编排中抽到可测试的查询/服务函数，路由只负责鉴权、参数和响应。
- 文件列表查询补来源消息摘要时继续复用现有 Space 与 Human 可读权限，不允许前端用裸 message ID 逐条补查。
- trajectory scope 的归属和 ambiguous 判定放在独立 helper/状态对象中，由 `AgentManager` 调用；不要把分支继续堆进 runtime adapter。
- Core 负责把 thread channel 归一到父会话，runtime adapter 不读取数据库，也不理解 Kith-space 的 thread 表结构。

## 12. 动画与响应式

### 12.1 聚合面板展开/收起

- 以 Chat 与右侧区域之间的物理边界为运动点，改变面板宽度或 grid/flex 轨道。
- 打开时边界向左移动并让出聚合面板；关闭时边界向右回收。
- 内容随边界裁切，禁止使用整体 `opacity` 淡入淡出。
- 使用会话/轨迹侧栏已经确认的响应速度，不改动 Module Pane 原有切换曲线。
- 点击后状态必须立即进入动画，不增加人为延迟、延后挂载计时器或重复测量造成的“顿一下”。

### 12.2 滑动 Tab

- 选中底板只做横向位移，文本颜色可以随选中状态同步变化。
- 不为三个内容页同时执行位移动画；内容切换保持直接，避免和面板边界动画叠加造成拖沓。
- 快速连续点击以最新 value 为准，不能排队播放多个旧动画。

### 12.3 宽度不足

面板优先级为：当前主要工作面 > Module > 聚合面板 > 固定会话列表。

- 三栏无法同时满足 Chat、聚合面板和 Module 最小可用宽度时，临时隐藏聚合面板并保留打开意图。
- Chat + Module 仍不足时，继续使用现有单 Pane 响应式规则。
- ChatOnly 中不足以同时容纳当前会话和聚合面板时，同样临时隐藏聚合面板，不把它改成覆盖抽屉。
- 窗口恢复宽度后按用户意图恢复，不生成收起长条。

具体阈值应进入 `paneConstraints.ts` 的纯计算边界并配套单元测试，不散落为多处 CSS magic number。

## 13. 无障碍与交互细节

- 所有纯图标按钮必须有稳定的 `aria-label`、Tooltip 和可见键盘焦点。
- 聚合面板开关、会话列表开关使用 `aria-pressed` 表达状态。
- 滑动 Tab 使用标准 tablist/tab/tabpanel 语义和键盘导航。
- 分类胶囊使用单选筛选语义，选中态不能只依赖颜色。
- 搜索展开后焦点进入输入框；关闭搜索后焦点回到搜索按钮。
- 面板收起时，若焦点位于面板内部，应先把焦点返回聚合面板开关。
- 动画遵循 `prefers-reduced-motion`。

## 15. 验收标准

### 15.1 标题与布局

- 页面不存在旧“会话 / Chat / 轨迹”顶栏。
- 标题左侧纯图标可展开/收起会话列表。
- 标题右侧依次提供任务、成员、聚合面板和既有更多操作；前三者均为纯图标。
- 任务图标打开当前会话 Tasks，不显示 Chat 内嵌任务 Tab。
- 聚合面板在 ChatOnly 位于 Chat 右侧，在 Split 位于 Chat 与 Module 之间。
- ModuleOnly 不单独显示聚合面板，恢复 Chat 后可恢复打开意图。

### 15.2 动画

- 聚合面板和会话列表沿边界横向平移/改宽，无淡入淡出和长条占位。
- 滑动 Tab 底板可在三项之间连续滑动，快速点击不排队、不迟钝。
- Module 切换继续使用自己的既有曲线，不被聚合面板曲线覆盖。

### 15.3 文件

- “全部 / 图片 / 视频 / 文件”分类准确且可与搜索组合。
- 搜索可以匹配中文或英文文件名以及来源消息正文。
- 搜索展开/收起、空结果和请求失败均有明确状态。
- 切换频道或 DM 后不会短暂显示上一会话文件。

### 15.4 话题

- 中文用户界面不再出现表示产品概念的“线程”，统一显示“话题”。
- 聚合面板展示当前会话全部话题，不受 Chat 当前消息分页影响。
- 点击话题后正文仍在现有 Chat/话题位置打开；聚合面板不渲染第二份正文。
- 无 Module 时保持父会话与话题五五开，Module 打开时紧凑 Chat 只显示话题。
- 关注铃铛、关闭按钮、拖拽宽度和跳回原消息不回归。

### 15.5 轨迹隔离

- 会话 A 的轨迹不会出现在会话 B 或 DM C。
- A 下话题产生的轨迹可以出现在 A 的聚合轨迹中。
- 无作用域和跨父会话 ambiguous 轨迹不进入任何会话面板。
- 切回本次前端会话中访问过的会话时，可看到其各自最近的有界轨迹。
- 切换 Space 后旧 Space 轨迹全部清空。

### 15.6 验证命令与真实运行

实现阶段至少执行：

```powershell
pnpm run typecheck
pnpm test --unit
pnpm test --integration
pnpm run web:build
```

浏览器真实验证至少覆盖：

- 1440 × 900：ChatOnly、Split 三栏、话题 + 聚合面板 + Module。
- 1280 × 800：面板边界动画和 Composer 高度不回归。
- 1024 × 768：聚合面板响应式临时隐藏和单 Pane 降级。
- 连续快速切换三项 Tab、快速展开/收起、切换频道/DM、浏览器前进/后退。
- Console 无 React key、状态更新、布局测量或可访问性相关错误。
