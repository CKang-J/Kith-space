# Kith-space 频道设置、归档与删除设计

- 日期：2026-07-14
- 状态：已实现、通过命令与浏览器验证并完成一次最终 review，待用户验收
- 范围：频道设置场景、常规/成员/通知页面、归档频道分组、频道恢复与删除、`# all` 必需频道保护
- 设计基线：`cdcfe4b`；实现位于 `codex/ui-adjustments`，与本规格同一提交交付

> 本文锁定频道管理 UI 与生命周期的目标状态；当前代码已经按本规格实现，命令与真实浏览器验证及按约定仅一次的最终 review 均已完成。当前产品事实以 `docs/kith-space/ui-direction.md`、`docs/kith-space/architecture-proposal.md` 和源码为准。

## 1. 决策摘要

频道设置不作为“轨迹 / 话题 / 文件”右侧的第四个常驻 Tab。前三项都是当前会话内容，设置则是低频管理场景；把两种层级并列会让聚合面板语义混乱，也会挤压 300px 宽度内的 Tab。

本轮采用以下结构：

- 继续从频道标题栏的设置图标进入。
- 点击设置后展开聚合面板，并用“频道设置”管理场景暂时替换聚合 Tab 和内容。
- 设置首页提供“常规 / 成员 / 通知”三个钻取页面，以及分离的归档和删除操作。
- 从设置退出时恢复此前选中的聚合 Tab、文件分类、搜索词与搜索展开状态。
- 单 Human 产品不显示“离开频道”；对应行为统一为“删除频道”。
- 归档是可恢复、只读的频道状态。归档频道进入会话列表中默认收起的“已归档”分组，不能再归档后无处寻找。
- `# all` 是每个 Space 的必需频道：界面隐藏归档和删除入口，服务端拒绝相关写操作；实现时还要自动恢复已经被误归档或软删除的 `# all`。

## 2. 目标与非目标

### 2.1 目标

- 把频道设置从居中弹窗改造成与当前单窗口信息架构一致的右侧钻取页面。
- 让常规、成员和通知拥有清晰、可扩展但不过度抽象的页面边界。
- 保留聚合面板作为唯一右侧辅助工作面，不增加第二套 Settings Module。
- 让归档成为可发现、可查看、可恢复的安全操作。
- 让删除成为单 Human 语义下唯一的不可恢复频道退出方式。
- 从 UI 和服务端两层保护 `# all`，并修复现有误归档数据。
- 明确归档频道的只读边界，避免归档后仍能发送消息或创建频道级内容。

### 2.2 非目标

- 不把频道设置放进 Dock Settings 模块。
- 不把“设置”加入 `SlidingTabs`，也不改变“轨迹 / 话题 / 文件”的顺序和状态保持规则。
- 不为 DM 伪造频道归档、成员或可见性能力；DM 后续可以拥有独立的“会话设置”方案。
- 不新增多 Human 管理员、所有者转移、离开频道或权限角色。
- 不在本轮实现已删除频道回收站或硬删除 SQLite 历史数据。
- 不把归档频道混入普通频道搜索、未读和活跃列表；需要查看时通过“已归档”分组进入。

## 3. 术语与生命周期

| 术语 | 产品语义 |
|---|---|
| 频道设置场景 | 聚合面板中的临时管理场景，不是聚合内容 Tab |
| 活跃频道 | 未归档且未删除，允许正常读写并显示在频道主列表 |
| 已归档频道 | 可恢复、只读，显示在默认收起的归档分组 |
| 已删除频道 | 产品层不可恢复；正常列表、搜索、收件箱和模块查询均不可见 |
| 必需频道 | 每个 Space 的 `# all`；不能归档或删除 |

频道状态转换固定为：

```text
活跃 ──归档──> 已归档 ──恢复──> 活跃
  │                │
  └────删除────────┴────删除──> 已删除
```

删除继续允许数据层保留 `deletedAt` tombstone 维护引用一致性，但产品不得把它描述成可恢复操作。若未来需要真正清理消息与附件对象，应作为独立的数据清理设计，不在本轮静默加入。

## 4. 聚合面板中的设置场景

### 4.1 默认内容场景

```text
┌──────────────────────────┐
│ [轨迹] [话题] [文件]      │
├──────────────────────────┤
│ 当前聚合内容              │
└──────────────────────────┘
```

### 4.2 设置首页

```text
┌──────────────────────────┐
│ ⚙ 频道设置             × │
├──────────────────────────┤
│ ⚙ 常规       当前频道名 › │
│ ♙ 成员             6   › │
│ ♧ 通知         所有消息 › │
├──────────────────────────┤
│ ▣ 归档频道…               │
│ 🗑 删除频道…               │
└──────────────────────────┘
```

- 设置首页替换整个 Tab 区和内容区，不显示第四个“设置”Tab。
- × 收起聚合面板；再次从普通聚合入口打开时恢复之前的内容 Tab，而不是自动回到设置。
- 从频道设置按钮再次进入时直接打开设置首页。
- 切换到另一个频道时关闭旧频道设置并回到原聚合内容场景，禁止把旧表单短暂显示在新频道。

### 4.3 子页面钻取

```text
┌──────────────────────────┐
│ ‹ 常规                 × │
├──────────────────────────┤
│ 页面内容                  │
└──────────────────────────┘
```

- 子页面返回：`常规 / 成员 / 通知 → 频道设置首页`。
- 设置首页返回：`频道设置首页 → 进入设置前的聚合内容 Tab`。
- 常规页面存在未保存修改时，返回、关闭、切换频道前确认是否放弃；成员和通知的即时操作不制造全局脏表单。
- 设置场景与子页面属于短暂 UI 状态，不写入 URL；频道深链接仍只表达当前会话和既有模块状态。

### 4.4 与 Module 和响应式的关系

- ChatOnly：设置显示在 Chat 右侧的聚合面板位置。
- Split：设置显示在 Chat 与 Module 之间，Module 不被替换。
- 普通聚合内容在宽度不足时继续按既有规则临时隐藏；但“打开频道设置”是明确用户动作，不能点击后无反馈。
- 当三栏宽度不足以显示设置时，复用同一设置组件，在 Chat 内以右侧临时抽屉呈现，不复制第二套表单，不覆盖 Module。
- Chat 不可见的 ModuleOnly 没有频道设置入口；恢复 Chat 后再从当前频道进入设置。
- 设置面板/抽屉沿物理右边界改宽并裁切内容，不使用淡入淡出。

## 5. 常规页面

常规页面包含：

- 名称。
- 描述。
- 可见性：公开 / 私密。
- 明确的“保存更改”按钮。

规则：

- 名称和描述作为一个显式提交批次，避免每次输入都发请求。
- 切换可见性需要二次确认，保存成功后刷新频道列表和当前标题。
- 错误在当前页面内展示，不能保存失败后直接关闭设置。
- `# all` 继续允许编辑描述；为保持当前必需频道识别稳定，名称与可见性不可修改，并展示“系统频道”说明。

## 6. 成员页面

成员页面只管理当前频道中的 agent 阵容：

- 顶部复用通用 `SearchField` 搜索当前成员。
- “添加成员”打开现有 Agent 选择能力，只列出尚未加入的当前 Space agent。
- 唯一 Human 固定显示为“你 · 管理员”，不能移除，也不进入多 Human 权限模型。
- agent 行展示头像、名称和必要的角色/状态；更多菜单只提供与该成员相关的频道操作。
- 添加或移除成功后即时刷新成员数、标题成员入口和当前列表。
- `# all` 仍允许管理 agent 成员，但不允许移除唯一 Human。

## 7. 通知页面

通知级别固定为：

| 选项 | 行为 |
|---|---|
| 所有消息 | 当前频道每条新消息都可触发本地 Human 通知 |
| 仅提及 | 只有明确 `@you` 或需要 Human 关注的事件触发通知 |
| 不通知 | 不弹本地通知；频道更新仍可进入收件箱与未读统计 |

- 单选后即时保存并提供轻量成功反馈。
- 通知设置只影响唯一 Human 的本地通知路由，不影响 agent 唤醒、消息持久化、未读数或收件箱规则。
- 数据归属继续放在 `human_channel_states`，建议增加受约束的 `notification_level = all | mentions | none`，默认值为 `all`。
- 该字段需要正式 schema migration 和读写测试，不能只保存在浏览器本地状态。

## 8. 归档频道分组

### 8.1 会话列表结构

```text
频道                         ＋
├─ # all
├─ # 产品讨论
└─ # 开发

› 已归档                    3
```

- 没有归档频道时整行不显示。
- 有归档频道时默认收起，只显示名称和数量。
- 展开状态是当前前端会话的本地 UI 状态，不进入 URL。
- 展开后按 `archivedAt` 倒序显示，使用弱化样式和归档图标。
- 归档频道不显示活跃未读徽标，也不计入频道主列表数量。
- `# all` 永远不能出现在归档分组；若历史数据中出现，先执行必需频道修复。

### 8.2 打开归档频道

点击归档频道仍使用规范频道 URL，并进入只读页面：

```text
该频道已归档，当前为只读状态。       [恢复频道]
```

- 历史消息、话题、文件、成员和频道设置可查看。
- Composer 禁用，不允许发送消息或“作为任务发送”。
- 不允许创建新话题、上传附件、添加回复或创建新的频道作用域任务。
- 已存在任务仍可在 Tasks 中查看；本轮不自动关闭或删除它们。
- 恢复后频道立即回到活跃列表并恢复正常写入。

### 8.3 数据查询

现有 `GET /api/channels` 默认排除归档频道，`?archived=include` 可以返回全部非删除频道。实现时补清晰的 `archived=only` 查询，Store 分别维护活跃和归档列表，避免页面各自重复过滤。

Socket `channel:updated` 后同时刷新两组列表，使归档和恢复在多个窗口中即时移动分组。

## 9. 归档、恢复与删除

### 9.1 归档

- 从活跃频道设置首页触发。
- 使用普通或警示色操作，不与红色永久删除混为一类。
- 确认文案明确说明“频道将变为只读，可随时恢复”。
- 成功后关闭设置，导航到可用的活跃频道，并让目标频道进入“已归档”分组。

### 9.2 恢复

- 归档频道顶部 banner 和设置首页都提供“恢复频道”。
- 恢复是幂等操作；成功后留在当前频道，并把它移动回活跃列表。

### 9.3 删除

- 单 Human 产品不显示“离开频道”。
- 活跃和归档频道都可以删除，但 `# all` 除外。
- 删除入口使用红色危险样式，并与归档/恢复通过分隔线隔开。
- 二次确认要求输入完整频道名称，确认按钮在匹配前禁用。
- 成功后关闭设置、移出全部频道列表，并导航到 `# all`。
- 产品不提供恢复已删除频道的入口；服务端现有 soft-delete tombstone 只用于数据一致性。

## 10. `# all` 必需频道保护与历史修复

只隐藏按钮不足以根治问题。必需频道约束必须集中在领域和 API 边界：

- 抽出单一 `isRequiredChannel` / `ensureRequiredChannels` 领域 helper，避免在 React、路由和数据库初始化中各写一份 `name === "all"`。
- `POST /api/channels/:id/archive` 对 `# all` 返回稳定的 `required_channel` 冲突错误。
- `DELETE /api/channels/:id` 对 `# all` 返回同一领域错误。
- 前端 `# all` 设置首页完全隐藏归档和删除行，不显示一个永远失败的禁用危险按钮。
- 常规页锁定 `# all` 的名称和可见性，防止破坏当前系统对必需频道的识别。
- Space 数据库打开/基线校验时执行幂等修复：找到该 Space 的 `all` 频道后清空 `archivedAt` 与 `deletedAt`。
- 当前已经被误归档的 `# all` 必须在实现后第一次加载时自动恢复到活跃频道列表，不要求用户手工改库。
- 修复只触碰必需频道的生命周期字段，不修改消息、成员、已读状态或创建时间。

本轮不为了这一约束增加新的系统频道表或通用策略引擎；先用集中 helper 固化现有单一必需频道事实。若未来出现多个系统频道，再单独引入稳定 `systemKey` 数据模型。

## 11. 服务端读写边界

实现不能只改 UI：

- 所有向频道发送消息、创建话题、回复话题、上传附件或创建频道任务的入口，在解析最终父会话后拒绝已归档/已删除频道。
- agent CLI 和 Human API 使用同一 guard，不能出现 Human 只读但 agent 仍能往归档频道发消息。
- 归档父频道后，其话题自动继承只读状态；不直接修改每个 thread channel 的 `archivedAt`。
- 普通频道列表、快速搜索、Inbox 聚合、未读汇总和 ambient agent 唤醒默认排除归档频道。
- 归档详情查询继续允许读取历史消息、话题摘要和文件，前提是请求属于当前 Space。
- 删除后的频道不再接受任何普通读写；保留 tombstone 的内部维护查询除外。

生命周期判断已经放入中立领域模块 `src/channels/channelLifecycle.ts`，路由、Human 状态、消息和任务入口复用；必需频道的原始 SQLite 修复 helper 位于 `src/db/requiredChannel.ts`，避免数据库层反向依赖 server。

## 12. 前端模块边界

已按以下职责拆分：

- `ChannelSettingsPanel`：设置场景导航、返回和关闭，不读取具体页面表单字段。
- `ChannelSettingsIndex`：常规/成员/通知摘要和生命周期操作。
- `ChannelGeneralSettings`：名称、描述、可见性与脏状态。
- `ChannelMemberSettings`：成员查询、搜索和增删。
- `ChannelNotificationSettings`：唯一 Human 的通知级别。
- `ArchivedChannelGroup`：会话列表中的折叠分组。

外壳职责：

- `WorkspaceFrame` 只组合路由与面板布局；`useChannelSettingsScene` 保存频道设置场景、脏状态退出、焦点恢复和浏览器历史后退保护，响应 Chat 的 `onOpenChannelSettings(channelId)`。
- `ConversationAggregatePanel` 在内容场景与设置场景之间切换，不把设置伪装成第四个 Tab。
- `Chat` 只发出“打开当前频道设置”的窄回调，并渲染归档频道只读 banner/Composer 状态；不要把三个设置页面继续堆入 `Chat.tsx`。
- 响应式聚合面板和 Chat 抽屉复用同一个设置内容组件，避免宽窄布局产生两套行为。

## 13. 状态、失败与无障碍

- 每个请求都有明确的 loading、失败和重试状态；失败不能自动退出当前设置页。
- 归档、恢复、删除成功后使用 Toast，并由 Socket/Store 结果刷新列表，避免只乐观改本地数组。
- 设置首页行使用按钮语义；子页面标题、返回和关闭具备清晰 `aria-label`。
- 单选通知使用原生 radio 语义；成员搜索复用 `SearchField`。
- 危险确认框初始焦点不能落在删除按钮；要求输入频道名后才启用。
- 面板关闭后焦点返回频道设置按钮；响应式抽屉关闭遵循相同规则。
- 常规页存在未保存修改时，面板返回/关闭、频道切换、模块隐藏 Chat、浏览器刷新和历史后退都必须先确认；取消后保留原 URL、表单与焦点上下文。
- 所有宽度动画遵循 `prefers-reduced-motion`。

## 15. 验收标准

### 15.1 设置场景

- 频道设置不作为第四个聚合 Tab。
- 点击设置后在聚合面板位置进入设置首页，并可钻取常规、成员、通知。
- 返回设置首页后再返回，可恢复进入设置前的聚合 Tab 和文件筛选状态。
- 模块打开时设置位于 Chat 与 Module 之间；宽度不足时有可操作的 Chat 内抽屉，不会点击无反馈。

### 15.2 归档

- 归档频道离开活跃列表并进入默认收起的“已归档”分组。
- 没有归档频道时不显示分组。
- 归档频道历史消息、话题和文件可读，但 Human 与 agent 均不能新增内容。
- 恢复后频道立即回到活跃列表并恢复写入。

### 15.3 删除与 `# all`

- 产品中没有“离开频道”文案或行为。
- 删除要求输入频道名称，完成后没有 UI 恢复入口。
- `# all` 设置中不显示归档和删除，名称与可见性不可修改。
- 直接调用归档/删除 API 也不能改变 `# all`。
- 当前误归档的 `# all` 在首次加载实现版本后自动恢复，不出现在归档分组。

### 15.4 通知

- 所有消息、仅提及、不通知三档可以持久保存并在重启后恢复。
- 不通知不会改变未读、收件箱或 agent 唤醒语义。
