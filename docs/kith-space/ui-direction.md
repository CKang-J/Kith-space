# Kith-space UI 方向

本文只写界面方向。技术实现、数据模型、迁移计划见同批次其余文档，此处仅在必要处带过。

结论前置：Kith-space 采用**双壳信息架构**——空间总览态是全局 bento 驾驶舱（个人 OS 门面），空间内部态以多 agent 群聊为 C 位、右侧模块化容器为辅。视觉学 OpenLoaf 的干净与丝滑。v1 把信息架构定死，视觉只做干净基础版，可拖拽 bento、画布、日历等 v1 之后长出。

---

## 1. 视觉方向

学 OpenLoaf：干净、好看、丝滑。这是本项目的视觉基准，不是模板化的"工作台皮肤"。

关键一点：本项目**不套用**用户 CLAUDE.md 里那套"去 AI 味"清单（字重、卡片、阴影、状态圆点、全大写等约束）。这是用户对本项目的明确特批（锁定决策 11）。设计师以 OpenLoaf 的质感为准绳，而不是以"去 AI 味"规则为约束。

落到执行上的取向：
- 以 OpenLoaf 的层次感、留白、过渡动效为参照，追求"丝滑"而非"极简克制"。
- 允许卡片、bento 分区、适度阴影与圆角——只要服务于 OpenLoaf 式的观感，不受"去 AI 味"清单限制。
- 视觉语言在总览态（bento 门面）和内部态（协作空间）之间保持同一套 token，壳变而气质不变。

需要说明：不套用"去 AI 味"清单，不等于放任视觉噪声。信息优先级依然要清晰，只是判断标准换成"是否贴近 OpenLoaf 的干净好看"，而非那份清单。

## 2. 双壳信息架构

Kith-space 有两个顶层壳，切换发生在"进入/退出一个空间"这一动作上（锁定决策 12）。空间（Space）在概念上约等于 OpenLoaf 的 project。

### 2.1 空间总览态 = 全局 bento 驾驶舱

这是整个应用的门面，是"我的整个 OS"视角：跨空间聚合，不属于任何单一协作。它是 OpenLoaf 那套可拖拽 bento 卡片的**正确归宿**——bento 留在这里当个人 OS 首页，而不是塞进空间内部的 C 位（锁定决策 16 / 13）。

聚合内容（完整形态）：跨空间的待办、日历、收件箱、agents 概览等，以可拖拽 bento 卡片铺陈。

v1 薄版只做三块：
- 空间列表（进入各空间的入口）
- 全局收件箱
- 简单的聚合待办

```
┌────────────────────────────────────────────────────────┐
│  Kith-space                                     [设置]   │
├────────────────────────────────────────────────────────┤
│                                                          │
│   ┌──────────────┐  ┌──────────────┐  ┌─────────────┐   │
│   │  我的空间     │  │  全局收件箱   │  │  聚合待办    │   │
│   │  · 空间 A     │  │  · @我的消息  │  │  · 今日 3 项 │   │
│   │  · 空间 B     │  │  · 任务更新   │  │  · 待审批 1  │   │
│   │  · + 新建     │  │              │  │             │   │
│   └──────────────┘  └──────────────┘  └─────────────┘   │
│                                                          │
│   （v1 之后：日历卡 / agents 卡 / 自定义可拖拽 bento）    │
│                                                          │
└────────────────────────────────────────────────────────┘
```

### 2.2 空间内部态 = 群聊 C 位 + 右侧模块化容器

点进一个空间，壳切换：左侧全局导航**收成竖直细图标条**（slim vertical icon rail），屏幕让位给协作。注意这条 rail 不是第二条底部 dock——右栏已经有自己的底部 dock，避免两条 dock 打架（锁定决策 15）。

```
┌────┬───────────────────────────────┬──────────────────┐
│ ▮  │                               │                  │
│    │                               │   模块化容器      │
│ #  │        多 agent 群聊          │  （任务/日历/     │
│ #  │        （常驻·C 位）          │   文件/轨迹/画布） │
│ @  │                               │                  │
│ @  │                               │                  │
│ ▸  │  ┌─────────────────────────┐  │                  │
│    │  │ composer                │  │ [任务][日历][文件]│
│ ⌗  │  └─────────────────────────┘  │ [轨迹][画布] dock │
└────┴───────────────────────────────┴──────────────────┘
  ↑左细图标条        ↑中群聊常驻      ↑↑可拖拽分隔·右栏可隐藏
```

左细图标条承载：空间内的频道、私聊（DM）、以及返回总览等入口，以图标形式竖排。

## 3. 空间内部态细节

### 3.1 中间：视图切换区，群聊为主视图

群聊是产品心脏、是中间区的**默认与主视图**：进入空间、点任一频道/DM，中间就是群聊，协作主线（对话、@唤醒、派活、汇报）都在这里。

**细化（对决策 13 的修正，用户 2026-07-10 拍板）**：中间区是一个**视图切换区**，不只承载群聊。左图标条上的管理入口——成员、机器、收件箱、搜索——点开后同样**占据中间区**打开（沿用旧 open-tag 侧栏的模式），而不是塞进右栏。群聊仍是主视图、随时点频道即回；但"群聊常驻、不可被切换"这一条放宽为"群聊是默认主视图，管理类视图可临时占用中间区"。这样保留了旧版顺手的管理入口，又不牺牲群聊的中心地位。

### 3.2 左图标条：导航入口（旧 open-tag 模式）

左细图标条承载空间内的导航入口，点击即在中间区打开对应视图：

- **频道 / 私聊（DM）**：并列同待遇，点开都在中间区显示为群聊。
- **成员**：agents（按机器分组）+ 人类 roster + 创建 agent 入口，点开占中间区。
- **机器 / Computers**：本空间机器列表 + 连接机器，点开占中间区（连接机器是跑 agent 的前提）。
- **本空间收件箱**：仅当前空间的 @我 / 未读 / 任务更新聚合（区别于总览态的**跨空间**全局收件箱）。
- **搜索**：点开占中间区（复用现有 Search 视图；OpenLoaf 重塑阶段再定是否改覆盖式）。
- **返回空间总览**。

它不是第二条底部 dock（右栏才有底部 dock）。

### 3.3 右栏与中间视图的关系

右栏模块容器（见 3.4）是**群聊的伴随面板**：当中间区显示群聊时，右栏可用（任务/日历/文件/轨迹/画布）。当中间区显示管理视图（成员/机器/收件箱/搜索）时，右栏默认隐藏，回到群聊时恢复——避免"看成员"时右侧还挂着任务板的错位感。DM 与频道一样，会话内容占中间、**不占右栏**（锁定决策 14）。

### 3.3 右栏：模块化容器 + 底部 dock

右栏是一个模块化容器，自带**底部 dock** 切换显示内容（锁定决策 14）：

```
右栏内容随 dock 切换
┌──────────────────┐
│                  │
│   当前模块视图    │
│  （如：任务板）   │
│                  │
├──────────────────┤
│ [任务][日历][文件]│ ← 底部 dock
│ [实时轨迹][画布]  │
└──────────────────┘
```

Dock 可切换：任务 / 日历 / 文件 / agent 实时轨迹 / 画布 等。

其中**实时轨迹只是众模块之一**，不是右栏的固定身份。它的特殊之处在于：它是配合默认 autopilot（锁定决策 7）的"透明度窗口"——agent 默认自动干活，用户通过实时轨迹模块看清它在做什么。它重要，但地位与其他模块平等。

### 3.4 左右可拖拽、右栏可隐藏

- 左细图标条与右栏之间、以及各区之间可**拖拽分隔**：自适应默认宽度 + 自由拖拽（锁定决策 15）。
- 右栏**可隐藏**：隐藏后群聊全宽，专注对话。

### 3.5 吃宽度的模块可提升到中间/全屏

画布、日历这类吃宽度的模块，可以从右栏**提升到中间乃至全屏**；此时群聊让位为侧边条（side strip）。这是 OpenLoaf 便当盒可调性的落点——右栏里"扫一眼"，中间里"专注做"（锁定决策 15）。

```
模块提升到中间时
┌────┬──────────────────────────────┬──────────┐
│ ▮  │                              │ 群聊      │
│ #  │        画布 / 日历（放大）    │ （侧边条）│
│ @  │                              │          │
└────┴──────────────────────────────┴──────────┘
```

## 4. 关键取舍说明

**为何群聊占 C 位，而非 OpenLoaf 式 bento 看板？**
Kith-space 的灵魂是"人和多个 agent 在同一空间协作"。协作发生在对话里——@唤醒、派活、汇报、追问都是对话动作。若把 bento 看板放 C 位，协作主线就被降级成一个模块，产品会滑向"个人生产力看板 + 附带聊天"，丢掉协作灵魂。所以 bento 被移到总览态当门面（它在那儿是对的），空间内部把 C 位牢牢留给群聊（锁定决策 13 / 16）。

**为何右侧是观测/模块面板，而非 OpenLoaf 式的单 AI 对话框？**
OpenLoaf 右侧放单 AI 框，是因为它的对话入口就在右边。Kith-space 的对话已经在中间群聊里了，右侧再放一个 AI 框是重复。更重要的是：默认 autopilot 下，agent 自动干活，用户真正需要的右侧内容不是"再开一个对话"，而是**看清 agent 在做什么**的透明窗口 + 可随手取用的模块（任务/文件/日历）。所以右侧定位为模块化观测容器，实时轨迹是其中的透明度模块（锁定决策 7 / 14）。

## 5. v1 UI 范围

- **信息架构现在定死**：双壳、群聊 C 位、右栏模块容器 + 底部 dock、DM 与频道并列、左细图标条、可拖拽分隔、右栏可隐藏、模块提升——这些结构 v1 就成立，不推迟（锁定决策 11）。
- **视觉做"干净基础版"**：以 OpenLoaf 气质为准做出干净、可用、顺滑的第一版，不追求精雕细刻的动效与视觉细节。
- **v1 之后长出**：总览态的可拖拽 bento 卡片、画布模块、日历模块，以及总览态的完整聚合（日历/agents 卡）等，v1 之后再补。v1 空间内部的右栏 dock 先落地与 v1 模块对应的项（结合决策 6，v1 模块 = 任务 + memory，日历/画布/文件为结构预留）。

一句话：**架构一步到位，视觉分阶段。**

## 6. 可复用的现有 open-tag UI 组件

底座是 open-tag（锁定决策 3）。以下组件行为可复用，但视觉层需按本文方向重塑。二创时保留交互行为、逐步拆分大文件，避免整块重写（探索报告 §4.1 风险提示）。

| 组件 / 文件 | 现状用途 | 在 Kith-space 的归位 | 需重塑处 |
|---|---|---|---|
| `web/src/views/Chat.tsx` | 频道/DM/thread 聊天 | 中间群聊 C 位（核心） | 文件偏大需拆分；视觉重塑为 OpenLoaf 气质 |
| `web/src/views/Composer.tsx` | 消息输入、@mention、附件 | 群聊 composer | 视觉重塑，保留 @mention/附件行为 |
| `web/src/views/Members.tsx` | 成员/agent 列表 | 左细图标条的 agent 呈现 + 右栏 agent 相关模块 | 文件偏大需拆分；从卡片式改为图标条/模块 |
| `web/src/TaskBoard.tsx` | 任务板 | 右栏"任务"模块（v1 模块之一） | 接入右栏容器 + dock 切换 |
| `web/src/store.tsx` | 前端状态 | 双壳状态、面板宽度、dock 选中态等新增状态的落点 | 文件偏大；需为双壳/可拖拽/dock 扩展状态，谨慎拆分 |
| inbox / mentions / saved 视图 | 收件箱、提及、收藏 | 总览态全局收件箱（v1 薄版核心之一） | 从空间内视图提升为跨空间聚合 |
| agent profile 视图 | agent 身份/职责 | agent 详情（从群聊/图标条进入） | 视觉重塑 |
| live trace 视图 | agent 活动轨迹 | 右栏"实时轨迹"模块（autopilot 透明窗口） | 接入右栏 dock，作为平等模块之一 |
| machine connect 向导 | 连接本机 daemon | onboarding 流程 | 视觉重塑 |
| agent workspace file browser | agent 工作区文件 | 右栏"文件"模块（结构预留） | 接入右栏 dock |

需**全新构建**（open-tag 没有、需新做）的 UI：
- 空间总览态的 bento 驾驶舱壳（v1 薄版：空间列表 + 全局收件箱 + 聚合待办）。
- 双壳切换机制与左侧全局导航 → 竖直细图标条的收起动画。
- 右栏模块化容器 + 底部 dock 切换框架。
- 左右可拖拽分隔、右栏隐藏、模块提升到中间/全屏的布局能力。

现有 open-tag 视觉偏 warm/editorial，卡片、pill、状态圆点、阴影偏多（探索报告 §4.1）；本项目按 OpenLoaf 气质重做视觉层，但注意本项目不受"去 AI 味"清单约束，重塑方向以 OpenLoaf 干净好看为准。
